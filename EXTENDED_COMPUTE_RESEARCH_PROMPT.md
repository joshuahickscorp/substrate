## Candidate necessity classes

Only these classes may earn a hardware-necessity proposal:

1. non-factorizable resident state exceeds the safe measured local working set;
2. scientifically necessary real-time latency is repeatedly missed under a fixed external deadline;
3. synchronized interaction cannot be serialized or replayed without changing the estimand;
4. a powered survivor requires so many independent units that a named decision deadline would be
   missed, and the deadline itself is justified.

The fourth class is normally throughput benefit, not necessity. Treat it as necessity only if delay
invalidates the decision and no sequential design answers it.

Rights, licenses, privacy review, missing natural inputs, participants, sensors, external
environments, power meters, and physical specimens remain non-compute gates.

- L0: current host with 300-minute adaptive operational legs and resumable serial work;

- L2: the smallest larger-memory Apple Silicon single node;

- L4: a small multi-accelerator node;
- L5: distributed or population-scale throughput;
