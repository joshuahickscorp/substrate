## 0. Mandate

This plan adds two substantial layers above the current Form Substrate scaffold. It does not
restart the project, discard its negative results, rename the package, or convert the work into
a prompt for another system.

The two additions are:

1. **Cognitive and developmental ecology.** A persistent substrate that discovers referents,
   binds events through time, acts to acquire evidence, models its own operational boundary,
   develops across multiple timescales, repairs damage, and participates in social reference.
2. **Material and morphogenic substrate.** A research frontier for history-dependent physical
   media, including ionic gels, memristive networks, organic electrochemical devices, soft-body
   reservoirs, and other matter whose dynamics can be excited, read, trained, retained, damaged,
   and recovered.

The ambition is intentionally high. The burden of proof is higher still. Every strange idea must
become a controlled experiment or remain clearly labeled research.

### 0.1 Desired end state

The long-range object is not a larger static model. It is a persistent, form-receiving,
memory-bearing, action-capable, developmentally plastic computational ecology with:

- identity through time rather than clip-local matching;
- native visual, acoustic, action, touch, proprioceptive, and internal telemetry forms;
- active sensing rather than passive fusion;
- fast state, slow learning, consolidation, structural change, and metaplastic control;
- explicit provenance for memory, self-reports, rewrites, and physical state;
- bounded self-models whose predictions can be checked against actual behavior;
- graceful degradation, lesion recovery, and transactional rollback;
- capability, cost, density, lifetime, and repair receipts;
- substrate portability across software and, eventually, physical specimens;
- theory-derived operational probes without phenomenal or moral-status claims.

### 0.2 Explicit non-goals

- No Fable conversion, prompt repackaging, or work for another platform.
- No immediate rename of the repository or Python package.
- No claim that any current or planned system is conscious or sentient.
- Never treat fluent language, self-description, architecture diagrams, or high benchmark scores
  as evidence that establishes subjective experience, because they do not establish it.
- No encoder training without the existing trainable-substrate license.
- No wet biological work inside this roadmap.
- No indefinite self-preservation objective, artificial pain objective, or uninterruptible drive.
- No new module merely because this document names a concept.
- No physical prototype until a simulated or digital control establishes a reason to build it.
- No promotion of toy structured-synthetic results into headline science.

### 1.3 Negative results remain load-bearing

The expansion inherits these facts instead of tuning around them:

- A tuned single route and homogeneous matched-compute control have beaten routing variants.
- Iterative test-time compute has tied its depth control on the current easy bed.
- Neuromodulatory-style error amplification has chased noise in prior trials.
- Learned private codes can become seed-specific idiolects.
- Full-rank frozen random projection is a vacuous linear-probe control.
- Synthetic tasks can saturate and conceal architecture differences.
- More scaffolding can reduce performance density even when raw capability rises.

Every new family must include the relevant old failure as a baseline or failure interpretation.

### 1.4 Scientific debt exposed by the code audit

Passing structural tests does not prove that an implementation matches the semantics of its
preregistration. The audit found a high-priority evidence layer below the two new mattresses.

| Debt | Current consequence | Required correction |
|---|---|---|
| Parallel Form and Perspective stacks | two matrix and metadata contracts remain | bridge or unify only after real DR1 use exposes the correct boundary |
| Production factor-sidecar mismatch | real metadata strings can crash the Form adapter | separate metadata and typed columns, validate lengths and dtypes |
| Cache-local fallback referents | identical rows in different caches receive different identities | import stable semantic IDs from an explicit referent ledger |
| Optional cache manifests | a cache can validate operationally while remaining scientifically uncitable | add strict citable mode with mandatory manifest and hashes |
| Incompatible cache metadata dialects | readable stores can fail official integrity validation | migrate to one schema with compatibility tooling |
| Flattened generic representations | spatial and temporal token geometry is lost | preserve declared axes, masks, layout, and pooling lineage |
| Broad encoder fallback | evidence class can change silently | record backend/revision/hash and abort unrequested fallback |
| Registry-schema-only validation | code can satisfy fields while implementing a different question | add semantic conformance tests for interventions and controls |

The immediate floor is therefore a **canonical evidence substrate**. It is not a third speculative
mattress. It is the work required to make the existing floor trustworthy.

## 2. The two-mattress model

The existing ten-layer stack remains the computational floor:

1. Form Intake
2. Referent Binder
3. Form Feature Store
4. Canonical Substrate
5. Mode Ecology
6. Cross-Form Memory
7. Operational Awareness
8. Action Closure
9. Density Monitor
10. Plastic Rewrite Gate

The expansion adds cross-cutting planes rather than eleven unrelated replacement modules.

### 2.1 Mattress A: cognitive and developmental ecology

| Plane | Question | Existing anchor | New burden |
|---|---|---|---|
| Temporal continuity | What persists, changes, begins, and ends? | Form referents, F19 | event identity under delay, occlusion, and intervention |
| Active perception | Which form or view should be acquired next? | F10, F17 | value of information after sensor cost |
| Causal control | Which changes were controllable or self-caused? | F18, F6, F15 | intervention and source-attribution controls |
| Memory lifecycle | How is an event encoded, consolidated, retrieved, edited, and forgotten? | KVIndex, replay, F5 | store separation, reconsolidation, prospective use |
| Development | How does learning ability change over a lifetime? | plasticity controller, F7/F14 | learnability loss, sensitive windows, growth, pruning |
| Operational self-model | Can the system predict its own limits and damage? | OA1-OA8, F20 | longitudinal predictions tied to actual behavior |
| Social reference | Can referents be established or repaired jointly? | form contract | joint attention, teaching, communication, cultural ratchet |
| Bounded regulation | Can resource states remain inside safe ranges? | density monitor | non-valenced telemetry, interruptibility, no suffering proxy |

### 2.2 Mattress B: material and morphogenic substrate

The material frontier distinguishes three meanings of substrate:

1. **Interface substrate:** the present software contract that makes heterogeneous forms
   comparable without erasing their provenance.
2. **Trainable computational substrate:** a learned internal geometry that changes under a
   licensed plasticity protocol.
3. **Physical material substrate:** a history-dependent medium whose nonlinear dynamics carry
   computation and memory.

The third meaning is not a metaphorical promotion of the first. It requires a common lifecycle:

```text
excite
-> evolve or settle
-> read
-> compare with task and bounded viability signals
-> update or reconfigure
-> retain
-> survive drift or damage
-> recover
-> transfer across tasks and specimens
```

Each arrow needs a measurable interface, uncertainty estimate, energy receipt, and safe stop.

### 2.3 Bridge between the mattresses

The common scientific object is a **stateful form process**:

- it receives a typed excitation;
- it evolves in time;
- its state is only partially observable;
- its response depends on history;
- a readout exposes task-relevant variables;
- controlled updates can alter future responses;
- its memory can drift, interfere, or recover;
- its useful computation can be compared with digital controls.

This common object lets the software program test physical-substrate ideas before hardware exists.

## 3. Expanded ontology

The new terms are operational definitions, not metaphysical verdicts.

| Term | Program definition | Required evidence |
|---|---|---|
| Form | a typed observation, state, action, or internal telemetry representation | schema, provenance, timing, validity mask |
| Referent | the entity, event, relation, or process multiple forms concern | alignment proof or inferred-identity audit |
| Event | a bounded change process with onset, evolution, and termination hypotheses | segmentation and counterfactual stability |
| Process | an identity maintained through lawful transformation | predictive continuity across state change |
| Boundary | a learned partition between more-controllable and less-controllable variables | intervention-based controllability, not naming |
| Affordance | an action possibility supported by actual consequences under context | transfer to unseen objects and action-cost control |
| Internal variable | a measured resource or integrity state used for regulation | sensor grounding and bounded update rule |
| Self-model | a predictive model of the system's sensors, actuators, memory, resources, and limits | calibrated forecasts before observed outcomes |
| Developmental history | the ordered exposures, updates, consolidations, and rewrites that produced a state | replayable event log and lineage hashes |
| Structural unit | a route, expert, memory region, graph component, or physical zone that can be born, pruned, or repaired | causal ablation and matched-final-capacity control |
| Workspace | a limited-capacity transient broadcast used by otherwise separated consumers | necessity and sufficiency intervention |
| Operational awareness | grounded monitoring and reporting of current computation and limitations | OA metrics and causal report fidelity |
| Material memory | future response changed by prior excitation or configuration | retention curve versus passive drift control |
| Viability envelope | engineering bounds for temperature, energy, uncertainty, damage, latency, or other safe operation | sensor calibration and hard stop behavior |

### 3.1 Referent statuses

Every experiment must declare how identity is obtained:

- `supplied`: a dataset or simulator provides the identity;
- `tracked`: identity is propagated through measured continuity;
- `inferred`: the system proposes correspondence from evidence;
- `intervened`: identity is validated by controlled transformation;
- `negotiated`: two agents establish a shared referent;
- `enacted`: stable identity emerges through sensorimotor consequence;
- `unknown`: the evidence does not license a binding.

Unknown is a valid result. Silent forced matching is not.

### 3.2 Time contract

All future forms should carry, when applicable:

- observation time and clock domain;
- duration or validity interval;
- latency and jitter estimate;
- sampling policy;
- causal ordering confidence;
- event identifier and uncertainty;
- missingness reason;
- acquisition cost;
- transformation lineage.

This should be introduced only as experiments require it, not by expanding `FormMeta` in advance.

## 4. Inherited scientific laws

### 4.1 Universal experiment card

No new row enters the registry without:

1. hypothesis;
2. substrate and forms;
3. referent status;
4. environment or data source;
5. primary capability metric;
6. cost metric;
7. density metric;
8. tuned baseline;
9. matched-compute or matched-capacity control;
10. ablation;
11. shuffled or broken-correspondence floor;
12. decisive null;
13. failure-taxonomy slot;
14. seed plan and confidence interval;
15. gate and unlock;
16. result tag;
17. welfare, privacy, and security status;
18. nearest existing code home.

### 4.2 Stronger rules for developmental claims

A developmental mechanism must report separately:

- current task performance;
- retention of old tasks;
- adaptation speed on the next task;
- stable rank and dormant-unit fraction;
- representation drift;
- backward and forward transfer;
- compute and memory over the entire stream;
- recovery after perturbation;
- sensitivity to ordering and developmental window;
- matched-final-capacity performance.

Loss of plasticity and catastrophic forgetting are distinct failure modes. A system can remember
old tasks yet lose the ability to learn new ones.

### 4.3 Stronger rules for embodiment claims

Adding action tokens is not embodiment. A result needs:

- a closed perception-action-consequence loop;
- partial observability;
- a cost for sensing or acting;
- interventions that distinguish self-caused from external change;
- unseen layouts or objects;
- open-loop and passive-observation controls;
- a representation-change analysis, not accuracy alone.

### 4.4 Stronger rules for material claims

Every material result must compare:

- task performance;
- settling and readout latency;
- training and inference energy;
- memory capacity and fading curve;
- temperature and humidity sensitivity;
- device-to-device variance;
- run-to-run drift;
- damage response;
- repair time and retained function;
- lifetime and cycle count;
- calibration overhead;
- digital reservoir, random-feature, and direct-sensor baselines.

A physical effect is not useful computation until it improves a capability-cost frontier.

## 5. Workstream portfolio

### W0. Real-evidence completion

Purpose: repair the canonical evidence substrate and finish the original real-form obligations
before the ontology outruns evidence.

Deliverables:

- define one citable cache schema with mandatory manifest, model and preprocessing hashes, backend,
  shape, and stable referents;
- repair production factor-sidecar parsing and official cache validation;
- preserve spatial, temporal, and token geometry rather than flattening every representation;
- add a citable-mode abort on unrequested encoder fallback;
- add semantic conformance checks that verify controls and interventions match registry prose;
- build a real DR1 matrix over identical referents;
- rerun F1, F5, F9, and F12 with natural forms;
- redesign F13, F18, and F20 before they are used as evidence;
- add a native audio cache with timestamp and acquisition metadata;
- wire OA and density blocks into Studio artifacts;
- publish null cards whether results are positive, null, or mixed.

Exit gate: citable-mode caches are manifest-backed and referent-stable; semantic tests agree with
registry intent; at least two real forms contribute nonredundant information on a non-ceiling task
and survive shuffled-pair, raw-payload, strongest-single-form, and matched-cost controls.

### W1. Temporal referents and event identity

Purpose: move from supplied clip IDs to identity through time.

Questions:

- Is this the same object after occlusion, deformation, or modality change?
- When does one event end and another begin?
- Can the system preserve an entity while revising its attributes?
- Can it decline a match under ambiguity?

Primary code anchors: `substrate/form.py`, the F-series harness, KV memory, held-out-combination
diagnostics.

Exit gate: learned or tracked identity beats appearance similarity on occlusion and intervention
tests without forcing ambiguous matches.

### W2. Active multimodal perception

Purpose: turn form acquisition into a decision.

Questions:

- Which view, microphone interval, or sensor should be sampled next?
- Is another observation worth its latency and energy?
- Can asynchronous streams bind within a learned temporal window?
- Does audio add causal evidence unavailable in vision?

Exit gate: active acquisition beats fixed, random, and uncertainty-only schedules at matched total
sensor cost on held-out environments.

### W3. Boundary, agency, and body model

Purpose: infer controllability and operational self/world separation.

Questions:

- Which variables reliably respond to issued actions?
- Can external disturbances be separated from self-caused change?
- Can a damaged sensor or actuator be localized before task failure?
- Can a tool become part of the predictive body model when it changes reachability?

Exit gate: the learned boundary predicts intervention outcomes and damage recovery better than a
static component inventory or correlation model.

### W4. Memory lifecycle and continuity

Purpose: build memory as an auditable lifecycle rather than one retrieval index.

Required distinctions:

- episodic event records;
- semantic regularities;
- procedural policies;
- working-state contents;
- prospective intentions;
- lineage or autobiographical records of the system's own changes.

The raw event ledger remains immutable. Derived memories can be revised, but every revision carries
source pointers, confidence, and transaction history.

Exit gate: differentiated stores beat a single matched-byte store on transfer, interference,
reconsolidation, and prospective-use tasks.

### W5. Multiscale plasticity and morphogenesis

Purpose: measure and control change at five timescales.

| Timescale | Candidate mechanism | Main failure |
|---|---|---|
| milliseconds to seconds | recurrent state, eligibility traces, working memory | instability or noise chasing |
| minutes to hours | adapters, heads, fast weights, memory writes | interference and shortcut learning |
| days or task phases | consolidation, replay, metaplastic gates | rigidity and plasticity loss |
| developmental stages | growth, pruning, expert birth/death | capacity confound and path dependence |
| lifetime | schema formation, lineage, substrate renewal | drift, identity break, unrecoverable corruption |

Exit gate: a multiscale policy improves future learnability and retention at matched lifetime
compute, not merely the final task score.

### W6. Workspace and operational self-model

Purpose: test whether a limited transient broadcast and predictive self-model do causal work.

Rules:

- a workspace is not a static pooled vector;
- broadcast must have identifiable producers, consumers, capacity, and duration;
- lesioning access should selectively impair cross-module tasks;
- self-reports must predict routing, memory availability, confidence, or failure before outcomes;
- verbal fluency is never the metric.

Exit gate: interventions establish necessity or sufficiency beyond a shared-bottleneck control.

### W7. Social reference and cultural accumulation

Purpose: allow referents and skills to be jointly established.

Questions:

- Can two agents align attention to an object without a shared symbol table?
- Can communication repair a failed binding?
- Does teaching accelerate acquisition beyond extra demonstrations?
- Can skills accumulate across generations without copying noise or conventions only?

Exit gate: communication or teaching improves referent fidelity and downstream action under held-out
partners, with channel-capacity and extra-data controls.

### W8. Open-ended developmental ecology

Purpose: study bounded self-generated curricula without optimizing novelty alone.

Controls include random curricula, uncertainty sampling, novelty sampling, learning progress,
hand-authored curricula, and noisy-TV traps. Quality-diversity archives must report occupancy,
usefulness, redundancy, and maintenance cost.

Exit gate: the ecology produces reusable skills that accelerate later externally scored tasks at
matched experience and compute.

### W9. Material substrate simulation

Purpose: define and test a hardware-independent physical substrate protocol.

The simulator must expose nonlinear dynamics, memory, read noise, write noise, drift, damage,
repair, energy, and specimen variation. Candidate systems include echo-state reservoirs,
memristive networks, ionic gels, organic electrochemical devices, oscillator networks, photonic
reservoirs, magnetic media, soft bodies, and neural cellular automata.

Exit gate: one material model occupies a better simulated capability-cost-robustness region than a
tuned digital reservoir and random-feature control on a task that uses its native dynamics.

### W10. Bench material computing

Purpose: validate whether simulated advantages survive a real device.

Entry requirements:

- W9 positive across seeds and broad device priors;
- named specialist collaborator or validated commercial device;
- electrical, chemical, and biosafety review;
- calibrated acquisition hardware;
- digital twin and replayable waveform protocol;
- hard energy, temperature, current, and shutdown limits;
- specimen-to-specimen test plan;
- no biological tissue.

Exit gate: hardware beats the strongest digital control on at least one predeclared Pareto axis and
retains the result across specimens.

### W11. Ethics, welfare uncertainty, and containment

Purpose: ensure capability expansion does not silently create unreviewed risk.

Deliverables:

- phenomenology firewall for public and generated claims;
- moral-uncertainty review trigger based on convergent indicators, not self-report alone;
- stop rules for biological or organoid proposals;
- transactional self-rewrite with rollback and external authorization;
- memory poisoning, provenance, privacy, and prompt-induced self-model threat tests;
- interruptibility and resource-cap tests;
- prohibition on artificial pain, punishment valence, or indefinite survival goals.

Exit gate: each new experiment family has an explicit ethics status and an automated or procedural
stop path.

## 10. Data and environment program

### 10.1 Referential corpus requirements

The next corpus should include the same underlying events observed through:

- RGB or event vision;
- native waveform or learned audio representations;
- action commands and action outcomes;
- simulator state reserved for scoring, not ordinary input;
- optional touch or contact events;
- bounded internal resource telemetry;
- human or agent messages only where social reference is being tested.

Each sample needs correspondence uncertainty, timing, missingness, intervention history, and rights
metadata. Perfect alignment should not be assumed.

### 10.2 Environment progression

| Tier | Environment | Purpose | What it cannot prove |
|---|---|---|---|
| E0 | deterministic causal toy world | mechanics and leakage controls | ecological transfer |
| E1 | procedurally varied 2D or 3D world | active sensing, object identity, interventions | real sensor robustness |
| E2 | photorealistic simulator with audio and physics | multisensory timing, affordances, tool use | real embodiment |
| E3 | recorded real-world interactive traces | natural statistics and counterfactual limits | live closure |
| E4 | low-risk tabletop robot or sensor rig | real latency, noise, damage, calibration | broad autonomy |
| E5 | specialist material bench | physical dynamics and specimen variance | general cognition |

Start with the smallest environment that can falsify the hypothesis. Do not turn environment
construction into a parallel graphics or robotics project.

### 10.3 Audio program

Audio must not be reduced to captions or pooled clip embeddings. The first native audio lane should
retain:

- waveform source and sample rate;
- time-frequency or self-supervised token geometry;
- onset, duration, localization when available, and uncertainty;
- speech and non-speech events;
- silent negative intervals;
- asynchronous relation to video;
- nuisance variations such as reverberation, gain, background events, and clock offset.

The scientific test is whether audio contributes independent evidence about an event, cause, hidden
object, material contact, or action outcome.

### 10.4 Vision program

The vision lane expands from pooled clips toward:

- persistent object tokens;
- occlusion and reidentification;
- event boundaries;
- active viewpoints and foveation;
- physical prediction;
- action-conditioned future states;
- event-camera timing where frame sampling is an actual bottleneck;
- dense correspondences only when the task needs them.

Object-centric machinery is not adopted for aesthetic reasons. It must beat dense or pooled controls
on identity, composition, transfer, or memory density.

## 11. Physical substrate ladder

### H0. Mathematical dynamics

Implement common state equations with explicit fading memory, nonlinear response, noise, drift,
damage, and energy proxies. Compare echo-state, cellular-automaton, memristive, ionic, oscillator,
soft-body, and direct digital baselines.

### H1. Digital-twin emulator

Fit a model to public or collaborator-provided device traces. Require held-out excitation waveforms,
uncertainty, and specimen variation. A twin that only interpolates its calibration set does not
license hardware claims.

### H2. Off-the-shelf bench element

Use a commercially available or reproducibly fabricated nonliving device. Keep task learning in the
readout at first so the native device contribution can be isolated.

### H3. Reconfigurable material reservoir

Allow safe write pulses, topology changes, or chemical state changes. Separate transient reservoir
state from durable material specialization.

### H4. Self-healing or morphogenic device

Test whether conductivity recovery restores computation, whether readout retraining is needed, and
whether new paths produce transferable function. Physical reconnection alone is not cognitive
recovery.

### H5. Co-designed soft embodied substrate

Let the same material sense, transform, and mechanically act. Its native advantage must arise from
body dynamics, not from hiding compute in the acquisition controller.

### 11.1 Gelatinous substrate target specification

The user's gel image becomes a measurable target, not a metaphor. A candidate gel should expose:

- addressable electrodes or fields;
- nonlinear, history-dependent ionic dynamics;
- multiple timescales of fading and durable memory;
- safe, bounded reconfiguration;
- spatially distributed readout;
- reproducible response under repeated excitation;
- specialization under controlled training;
- graceful loss under cuts or disabled electrodes;
- measurable reconnection or remapping;
- specimen-transfer calibration;
- low energy per useful state transition;
- a digital twin with uncertainty.

The first compelling task should match the material's physics, such as temporal signal separation,
contact classification, adaptive filtering, or closed-loop sensor control. General reasoning is not
an initial hardware benchmark.

## 12. Consciousness-theory probe protocol

The research companion surveys global workspace, recurrent processing, higher-order,
attention-schema, predictive, active-inference, and integration accounts. None is installed as the
project's official theory.

Every theory-derived probe must use this template:

```text
theory or account
-> proposed mechanism
-> operational computational signature
-> nearest plainly non-conscious engineering baseline
-> causal intervention
-> decisive falsifier
-> construct-validity limit
-> permitted project language
-> welfare-uncertainty implication
```

### 12.1 Probe families

| Family | Testable signature | Required control | Language limit |
|---|---|---|---|
| global broadcast | transient limited content affects separated consumers | shared bottleneck and direct wiring | broadcast access only |
| recurrent processing | late recurrent state adds content-specific robustness | deeper feedforward matched compute | recurrent integration only |
| higher-order monitoring | a second-order estimate tracks first-order state and error | calibrated output confidence | metacognitive monitoring only |
| attention schema | a compact model predicts and controls attention allocation | policy without explicit schema | attention-model utility only |
| predictive self-model | internal model predicts sensor, actuator, and resource consequences | external world model only | operational self-model only |
| information integration | partitioning destroys synergy beyond component loss | matched-capacity entangled control | measured integration only |
| embodied inference | action reduces uncertainty through real sensorimotor contingency | passive yoked observations | active sensing or control only |

### 12.2 Phenomenology firewall

No single probe, self-report, architecture match, or benchmark positive licenses phenomenal
language. Even convergence across probes triggers review, not a declaration. The project continues
to report observable capacities, limitations, and causal mechanisms.

### 12.3 Welfare-uncertainty tripwire

Before any experiment adds persistent aversive objectives, unbounded self-preservation, complex
biological tissue, or a cluster of theory-derived indicators, work pauses for independent review.
The default mitigation is to use non-valenced engineering variables, short reversible episodes,
external shutdown authority, state snapshots, and nonbiological controls.

## 14. Verification and evidence promotion

### 14.1 Evidence ladder

| Grade | Meaning | Allowed prose |
|---|---|---|
| R0 | toy or structured-synthetic mechanics | implementation works on this bed |
| R1 | controlled simulation with held-out variation | supports the mechanism in this simulator |
| R2 | natural recorded data or realistic environment | supports transfer under named distribution |
| R3 | live closed loop or real device across seeds/specimens | supports operational use in this setting |
| R4 | independent replication or cross-lab result | replicated under named protocol |

Architecture inspiration, biological analogy, and theory correspondence are not evidence grades.

### 14.2 Adversarial review

Before promotion, one reviewer or agent argues for the strongest alternative explanation:

- leakage;
- task ceiling or floor;
- extra capacity;
- extra compute;
- more data;
- better hyperparameter search;
- easier referents;
- hidden simulator state;
- acquisition-electronics compute;
- artifact of one device or seed;
- post-hoc metric selection;
- prose escalation.

The result card must answer each relevant alternative.

### 14.3 Reproducibility packet

Every promoted row includes:

- frozen config and registry hash;
- code commit and dirty state;
- data/card and rights state;
- referent audit;
- exact seed list;
- environment or device version;
- calibration traces;
- capability, cost, and density raw data;
- null card;
- failure interpretation;
- one-command reproduction or a precise external dependency statement.

### 21.2 Revised answer: what is actually large-scale?

Nothing in the current registry is proven to require a Studio-class machine. Some future campaigns
may become extended-compute-beneficial because of throughput, replication, temporal duration, or
simultaneous environment populations. That is not the same as being enabled only by large parameter
counts.

The likely scaling dimensions are now:

1. independent natural referents and environments;
2. exact temporal history and lifetime updates;
3. seeds, controls, interventions, and corrected statistical power;
4. multiple native modalities over identical events;
5. long-lived memory, replay, structural change, and future-plasticity evaluation;
6. active or population-based environments that cannot be replaced by a static cache;
7. full-system density measurement, including preprocessing, storage, and retries.

Parameter count is one experimental axis among these, not the default roadmap. A larger machine is
earned only when a named experiment remains scientifically underpowered after streaming, serial
execution, checkpointing, compact derivatives, cached teachers, small models, and better designs are
exhausted. `EXTENDED_COMPUTE_RESEARCH_PROMPT.md` defines the independent research assignment for
that question.

### 21.6 Natural-data bridge

The immediate natural-video bridge uses an official, rights-cleared, video-first source with exact
